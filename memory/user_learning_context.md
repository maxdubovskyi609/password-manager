User is 16 years old and currently learning programming. They have access to Claude for about three weeks (starting around 2026-10-05) and want to use that time as effectively as possible for learning.

The `password_manager` project (CustomTkinter + SQLite desktop app) was built specifically for learning and gaining experience — not a production tool. They completed an OOP refactor (PasswordDatabase class, PasswordManagerApp(CTk) + BaseWindow(CTkToplevel) subclasses for each dialog) around 2026-10-13, writing the code themselves with guidance/review rather than having it written for them. As of 2026-10-13 they've decided to move on to a different, second project (not yet chosen) rather than keep polishing this one — reasoning: a portfolio with two differently-skilled projects beats one over-polished CRUD app.

**How to apply:** Given the short window and learning goal, favor teaching over doing — explain concepts, suggest they write code themselves where it's a learning opportunity (especially for the OOP refactor), and check understanding rather than just handing over finished implementations. Still write code directly when the task is about getting something working (e.g., the encryption feature) rather than a deliberate learning exercise — use judgment on which mode fits the moment, and ask if unclear.
